# شناسنامه ساختمان — دموی استاتیک

رابط فارسی و راست‌به‌چپ برای مشاهده مشخصات یک ساختمان پس از اسکن QR و پنل آزمایشی واحد کنترل نظارت. این پروژه از **Tailwind CSS 4، Alpine.js 3، Motion و Leaflet** استفاده می‌کند و هیچ دیتابیس یا سروری برای داده‌ها ندارد.

## اجرای سریع

خروجی آماده در پوشه `dist` قرار دارد. داخل پوشه اصلی پروژه، برای اجرا با سرور ساده:

```bash
python3 -m http.server 8081 --directory dist
```

سپس `http://localhost:8081` را باز کنید. اگر پورت اشغال بود، شماره دیگری انتخاب کنید. می‌توانید پوشه `dist` را روی هر هاست استاتیک، از جمله Replit یا Vercel، قرار دهید. بازکردن مستقیم فایل HTML ممکن است در بعضی مرورگرها دسترسی نقشه و ذخیره محلی را محدود کند؛ سرور ساده پیشنهاد می‌شود.

## امکانات

- رابط واکنش‌گرا، فونت محلی وزیرمتن، رنگ‌بندی روشن و نشان آپلودشده.
- نمایش تعداد طبقات، سطح اشغال، مساحت زمین و هر ۱۶ نقش درخواست‌شده.
- فیلتر عوامل بر اساس گروه و جستجوی نام یا تخصص.
- نقشه Leaflet دانشگاه امام محمد باقر (ع) ساری، مازندران با پین قابل کلیک، نمایش آدرس، زوم، بازگشت به موقعیت و مسیریابی.
- جابه‌جایی با دو انگشت در نقشه داخل صفحه؛ اسکرول معمولی صفحه حفظ می‌شود. روی کامپیوتر، برای زوم با چرخ ماوس کلید Ctrl یا ⌘ را نگه دارید.
- نمای بزرگ نقشه با حرکت آزاد، کنترل‌های لمسی و بستن با کلید Escape؛ اندازه نقشه با تغییر ابعاد صفحه اصلاح می‌شود.
- نقشه از سرویس استاندارد OpenStreetMap بارگیری می‌شود؛ هیچ API Key یا ثبت‌نامی برای این نسخه نیاز نیست. پین سفارشی و سبک روشن حفظ شده‌اند.
- نمایش نقشه و مسیریابی به اینترنت نیاز دارند. هنگام قطع اتصال یا خطای سرویس، پیام روشن و دکمه تلاش مجدد نمایش داده می‌شود؛ با برگشت اینترنت، بارگیری خودکار دوباره انجام می‌شود.
- کد QR واقعی برای نشانی فعلی صفحه و کپی لینک.
- ورود بدون پیامک با هر شماره موبایل معتبر ایران؛ ارقام فارسی، عربی، انگلیسی و پیش‌شماره `+98` پشتیبانی می‌شوند.
- مشاهده گزارش‌های ناظرین و مجری، جواب آزمایشگاه بتن و خاک، نامه‌ها و دریافت نسخه متنی هر مدرک.
- تب مهندسان داخل پنل با ۱۳ مهندس پروژه و شماره تماس تستی گرفته‌شده از شماره ورود.
- ثبت گزارش، اعتبارسنجی فرم، ذخیره خودکار پیش‌نویس به تفکیک شماره موبایل، جستجو و فیلتر گزارش‌های من.
- نگهداری گزارش‌ها در `localStorage` همان مرورگر و باقی‌ماندن آن‌ها پس از تازه‌سازی.
- گزارشات مردمی تخلف و تشویقی بدون ورود، همراه عکس، پیش‌نویس و سوابق ثبت محلی.
- حالت کاهش حرکت مطابق تنظیمات سیستم، مسیرهای صفحه‌کلید و مدیریت فوکوس پنجره‌ها.

## شماره مهندسان در پنل کنترل نظارت

بعد از ورود، تب «مهندسان» باز می‌شود. مهندسان طراح، ناظر، سرپرست، نقشه‌بردار، ترافیک و شهرساز از همان فهرست عوامل پروژه در این تب تکرار می‌شوند. شماره واردشده هنگام ورود برای همه آن‌ها به‌عنوان شماره تستی نمایش داده می‌شود. شماره واقعی هیچ مهندسی در داده‌های پروژه ثبت نشده است.

شماره‌ها و لینک تماس فقط هنگام حضور در تب مهندسانِ پنل ساخته می‌شوند؛ در صفحه عمومی و بعد از خروج، کارت‌های شماره تماس از DOM حذف می‌شوند. ورود مجدد با شماره دیگر، شماره تمام کارت‌ها را تغییر می‌دهد. جستجوی این تب مستقل از جستجوی عوامل در صفحه اصلی است.

این رفتار مربوط به دموی استاتیک است؛ احراز هویت و کنترل دسترسی واقعی همچنان نیازمند بک‌اند هستند.

## گزارشات مردمی

از گزینه «گزارشات مردمی» در منوی بالای صفحه یا نوار موبایل، فرم گزارش تخلف یا تشویقی را باز کنید. عنوان و متن الزامی‌اند؛ نام و شماره موبایل درخواست نمی‌شود. گزارش‌ها در همان مرورگر و برای همین پروژه ذخیره می‌شوند و پس از تازه‌سازی صفحه، متن و عکس‌های آن‌ها قابل مشاهده‌اند.

در هر گزارش می‌توان حداکثر ۳ عکس JPG، PNG یا WebP، هرکدام تا ۸ مگابایت، افزود. عکس‌ها در خود مرورگر کوچک و به JPEG تبدیل می‌شوند. پیش‌نمایش بزرگ، حذف عکس پیش از ثبت و بازیابی پیش‌نویس وجود دارد. Escape ابتدا پیش‌نمایش عکس و سپس فرم را می‌بندد.

گزارش مردمی به کارشناس ارجاع نمی‌شود و وارد پرونده گزارش‌های ناظر و مجری نمی‌شود. هیچ متن یا عکسی به سرور ارسال نمی‌شود. شناسه نمایش‌داده‌شده فقط شناسه ثبت محلی است و کد پیگیری سازمانی محسوب نمی‌شود.

در صورت پر یا غیرفعال بودن فضای مرورگر، فرم و عکس‌ها حفظ و خطا نمایش داده می‌شود. پاک‌کردن داده‌های مرورگر، سوابق محلی را هم حذف می‌کند. فقط گزارش‌های همین مرورگر نمایش داده می‌شوند؛ این بخش خبرخوان مشترک همه کاربران نیست.

## ویرایش و ساخت مجدد

```bash
npm ci
npm run build
npm run check
```

| فایل | کاربرد |
| --- | --- |
| `dist/index.html` | ساختار صفحه و قالب‌های Alpine |
| `dist/assets/app.js` | داده‌های نمونه، فرم‌ها، ذخیره محلی و وضعیت پنجره‌ها |
| `dist/assets/citizen-reports.js` | گزارشات مردمی، آماده‌سازی عکس، پیش‌نویس و سوابق مستقل |
| `dist/assets/project-map.js` | کنترل Leaflet، OpenStreetMap، خطای اتصال و تغییر اندازه |
| `src/styles.css` | Tailwind و سبک‌های اختصاصی |
| `dist/assets/building.svg` | تصویر شماتیک معماری |
| `dist/assets/logo.png` | لوگوی شفاف با نوشته «شناسنامه ساختمان»؛ ویرایش‌شده با imagegen |
| `scripts/build.mjs` | کامپایل Tailwind و قرار دادن وابستگی‌های محلی |
| `scripts/check.mjs` | بررسی جریان‌های اصلی دمو در DOM |

پس از تغییر کلاس‌ها یا سبک‌ها، `npm run build` را اجرا کنید. خروجی HTML، CSS، فونت و کتابخانه‌های JS به CDN وابسته نیستند.

## داده‌های نمونه

برای تغییر اسامی، نقش‌ها، گزارش‌ها، آزمایشگاه‌ها و نامه‌ها، آرایه‌های ابتدای `dist/assets/app.js` را ویرایش کنید. مشخصات عمومی ساختمان در `dist/index.html` قرار دارند. اطلاعات همه اشخاص و ساختمان فرضی است؛ دانشگاه صرفاً موقعیت نمونه نقشه است.

موقعیت نمونه فعلی، دانشگاه امام محمد باقر (ع) در ساری، استان مازندران، بلوار خزر، خیابان شهید مطهری است. مختصات نشانگر `36.57884, 53.05448` در محدوده [محوطه دانشگاه در OpenStreetMap](https://www.openstreetmap.org/way/240907314) قرار دارد. برای جابه‌جایی موقعیت، مرکز و اطلاعات نشانگر را در `dist/assets/project-map.js` و آدرس، مختصات و هر دو لینک مسیریابی را در `dist/index.html` هماهنگ کنید.

گزارش‌های جدید و پیش‌نویس‌ها فقط روی همان دستگاه، مرورگر و دامنه باقی می‌مانند. ورود این نسخه احراز هویت واقعی و محدودیت دسترسی امن ایجاد نمی‌کند. داده‌های بخش کارشناسی در سورس استاتیک موجودند. هنگام اتصال به بک‌اند، احراز هویت و کنترل دسترسی باید سمت سرور انجام شوند.

## وضعیت بررسی

۲۰ بررسی خودکار شامل ورود، عوامل پروژه، شماره تستی مهندسان در پنل، گزارش‌های ناظر و مجری، آزمایشگاه، نامه‌ها، نقشه و گزارشات مردمی است. عدم نمایش شماره‌ها در صفحه عمومی، حذف آن‌ها بعد از خروج، نشست بازیابی‌شده، ورود با شماره دوم و جستجوی مستقل مهندسان بررسی می‌شوند. برای بخش مردمی، ثبت تخلف و تشویق بدون ورود، پیش‌نویس، عکس، سوابق مستقل، نمایش امن متن، محدودیت فایل، لغو بارگذاری و خطای فضای ذخیره بررسی می‌شوند. رمزگشایی عکس در آزمون DOM شبیه‌سازی می‌شود.

ثبت گزارش تشویقی با یک فایل PNG واقعی، تبدیل آن به JPEG، نمایش بزرگ و بازیابی متن و عکس پس از تازه‌سازی در مرورگر دسکتاپ هم بررسی شد. رفتار موبایل با ابعاد شبیه‌سازی‌شده و سبک‌های واکنش‌گرا بررسی می‌شود؛ آزمون روی گوشی واقعی انجام نشده است.

بررسی نقشه با Leaflet واقعی شامل زوم، پین، بازگشت به موقعیت، تغییر اندازه، کنترل دو انگشتی، نمای بزرگ، خطای کامل و جزئی کاشی‌ها و اتصال مجدد است. خطاهای اتصال در آزمون DOM شبیه‌سازی می‌شوند. در پیش‌نمایش مرورگر ابری، سرویس کاشی OpenStreetMap پیام محدودیت استفاده نشان داد؛ این مورد محدودیت مشاهده‌شده سرویس نقشه در محیط بررسی است.
